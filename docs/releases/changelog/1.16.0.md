# What's New in 1.16.0 — Shared Plugin Core, AST Neighborhood Recall, a Verifiable Graph-First Rule & an Honest Catalog

- **One shared implementation behind four of the six harness plugins (`plugins/core/`):** the OpenCode, Claude Code, Codex and GitHub CLI plugins are now 13-line adapters that re-export a single shared core (`plugins/core/index.ts`, ~1.8k lines, Node built-ins only). A bug fix in the core reaches all four at once instead of four edits. The core is embedded in the binary (`include_str!`) and installed into `.NeuroStrata/plugins/core/` on init — no npm install required. **The Hermes (863 lines) and OpenClaw (1000 lines) bundles still carry their own implementations and were not converted to the shared core in this release.**
- **AST neighborhood recall (`neurostrata_memories_for_file`, `include_ast_edges`, default `true`):** one lookup now returns the file's governing memories, its 1-hop `DEPENDS_ON` / `RELATES_TO` neighbours and `SUPERSEDES` targets, and a compact AST summary — `symbols`, `callers`, `callees`, `imports`, `importers`, `blast_radius_count` — so an agent sees the blast radius before it edits.
- **Daemon-backed active-task resolution (`src/server.rs`, `src/task/mod.rs`):** `neurostrata_guard_validate` falls back to the `session_id` of the active `in_progress` task when the caller's `session_id` is empty or `"unknown"`; `neurostrata_task_list` returns `session_id` and `subagent_prompt_injection` on `in_progress` rows, so a stateless plugin resolves the active task and its prompt in one call.
- **Dynamic subagent prompt injection (`plugins/core/index.ts`):** `enrichAndInjectSubagentPrompt` prefetches the governing memories of every repo-relative file path named in a subagent prompt and embeds them, alongside the daemon's `subagent_prompt_injection`, in the injected header.
- **A verifiable Graph-First rule predicate (`src/task/mod.rs`, `plugins/core/index.ts`):** the rule no longer carries the prose bypass "unless the parent prompt states" — it names a check an agent can actually run: for any file it touches that is not listed under `### NeuroStrata Task & Graph Context`, call `neurostrata_memories_for_file` first.
- **Six field-audit bugs fixed.** (1) *The OpenCode plugin was never loaded* — `wire_harness_config` wrote `.opencode/neurostrata-plugin.json`, a file OpenCode does not read, and merged into a root `opencode.json` under a `"plugin"` key only when that file already existed; it now writes the `.opencode/plugins/neurostrata.js` loader OpenCode auto-discovers and always creates or merges `.opencode/opencode.json` → `"plugins"`. (2) *The plugins hardcoded the namespace `NeuroStrata`*, so the guard and the task list read the wrong namespace outside this repo — `resolveConfig` now resolves it from plugin config → `NEUROSTRATA_NAMESPACE` → the discovered project root. (3) *Tool classification was incomplete and the OpenCode V2 Code Mode path was invisible* — `TOOL_CLASSIFICATION` and the `is*Tool` predicates are now explicit, and `inspectCodeModeExecution` extracts `id` / `session_id` / `note` / `path` from a Code Mode `execute` payload. (4) *Hook handling was per-harness* — `handleHookEvent` / `handleClaudeHookEvent` now handle `PreToolUse` and `Stop` identically across harnesses. (5) *The governing memories of a file never reached the model* — the recall block is now delivered in `execute.before` and `execute.after`, and the Rust and TypeScript sides of `.NeuroStrata/session_queries.json` write one shape. (6) *The scaffolded pre-commit hook assumed a Rust `src/<module>/` layout* and so checked nothing in a Go, TypeScript or Python repository — it is now layout- and language-agnostic.
- **Build and platform fixes.** `build.rs` now passes `/FORCE:MULTIPLE` on `windows-msvc` instead of the GNU-only `--allow-multiple-definition`; `tokenizers` builds with `default-features = false, features = ["onig"]`; `openssl` is vendored for every target; the daemon's `/graph` and `/export-graph` routes no longer return 500 when the config file cannot be read.
- **An honest feature catalog — and an honest catalog across the whole docs tree.** `docs/FEATURES.md` is re-headered for v1.16.0 and its false claims are corrected: the search row no longer claims Reciprocal Rank Fusion, Personalized PageRank or a FlashRank reranker (none exist — the three modes are alternatives, not a fused pipeline); the RDF/SPARQL/OWL/SHACL rows name the crates that are actually dependencies (`oxrdf` / `oxttl` / `spargebra` / `sparopt` / `spareval` / `sparesults` / `oxiri` / `shacl`) instead of the `oxirs-*` family, which was never a dependency (`petgraph` is a dependency too, but it backs the in-memory graph `leiden-rs` operates on, not the closure); the AST ingestion row states the six languages that are actually parsed (`rust`, `typescript`, `tsx`, `python`, `go`, `java`) instead of eleven; the embedder is `NomicEmbedTextV15` at 768 dimensions rather than `BGESmallENV15` at 384; only Leiden exists (no Louvain) and only `sha2` is used (no `blake3`); and six dead source paths now point at the modules that exist.
- **The same sweep ran across the rest of the documentation.** `README.md`, `docs/README.md`, `docs/COGNITIVE_ARCHITECTURE.md`, `docs/UI_GUIDE.md`, `docs/ops/cli-reference.md`, `docs/ops/security.md`, `docs/organs/dendritic-bridge.md`, `docs/organs/prefrontal-cortex.md`, `docs/architecture/synapticgraph.md`, `docs/science/nomenclature.md`, `docs/science/why-memory-fails.md`, `.agents/skills/neurostrata/SKILL.md` and `.agents/agents/NeuroStrata-Task.md` now name only MCP tools that are actually registered (the authoritative surface is the **56 tools** in `src/server.rs` `tools/list` — the 50 in the array plus the 6 SynapticMesh tools that `tools.extend(crate::synaptic_mesh::synaptic_mesh_tool_definitions())` appends to it), only CLI commands that actually exist (`learn`, not `learning`; `laya`, not `laya-export`; there is no `gliner` subcommand; the mesh subcommands are `push` and `pull`, not `sync` and `conflicts` — the one `sync`-named mesh command is the hidden `sync-enqueue`, the pre-push hook's target, which is not a user-facing transport command), the real `ValidateVerdict` variants instead of `ALLOW` / `WARN` / `BLOCK`, and the real Podman sandbox flags.
- **A second source-verified pass fixed eleven more claims.** The gate was credited with scanning diffs for `TODO`/`FIXME` markers (it never did — its task conditions are `in_progress` tasks, unextracted `done` tasks and P0 tasks open over 24 hours, and it also blocks on rule honesty: a live rule with no `metadata.source`, an unknown `metadata.enforcement` value, an `ENFORCED` claim naming a missing or advisory guard, a `PARTIAL` claim without a real guard, a `NOT_ENFORCED` claim that still names one, or a guard with no enforcement value — `src/task/gate.rs:399-530`); the Breath checkpoint was described as advisory (it is a hard `BreathRequired` block at five mutations without a note); the Episodic Buffer was documented as `*.jsonl` (it is the rolling Markdown file `.NeuroStrata/sessions/current.md`); the SynapticMesh CLI was given `sync` and `conflicts` subcommands and a `--namespace` flag on `status` (the visible surface is `init` / `join` / `push` / `pull` / `status` / `leave` / `recover`, `status` takes no flags, and the only other variant is the hidden `sync-enqueue` — the pre-push hook's internal target, not a user-facing transport command); the crash-breadcrumb directory and store path were wrong (`~/.config/NeuroStrata/data/db/crash/` and `~/.config/NeuroStrata/data/db/ladybug.db`) and the breadcrumb was described as carrying the binary version, commit hash, target triple, panic payload and lock/WAL state, none of which it records (it carries the signal, pid, thread id, epoch, alternate-stack size and an optional backtrace, and there is no panic hook at all); the build page described a macOS x64 runner and five release targets (CI is `ubuntu-latest` / `windows-latest` / `macos-15` arm64, and `release.yml` publishes four targets), a `lbug` pin of 0.15.x (it is 0.20.4) and a `recovering_config()` that does not exist (WAL behaviour is governed by `strict_wal_verification()`); the `guard_rule` shape was wrong (there is no `metadata.guard_rule` sub-object, and `trigger_pattern` is a case-insensitive substring match, not a regex); the Podman section did not say how the sandbox is invoked (it now carries the exact `podman run` line, the 5-second timeout and the `bash` / `script` scoping rule); the store's relations were listed as including `CALLS` and `IMPORTS` (the five typed relations are `RELATES_TO`, `CONTAINS`, `GOVERNS`, `EXTRACTED_FROM`, `DEPENDS_ON` — AST calls and imports are metadata arrays); `petgraph` was credited with the OWL/RDFS closure (it backs `leiden-rs`; the closure is in-house); and the Self-Reinforced Testing Framework page described LanceDB, a `bd`/Beads tracker and a `neurostrata_generate_canvas` tool (the store is LadybugDB, `bd` is deprecated in favour of the NeuroStrata task tools, and `neurostrata-mcp export-graph` is what ships).
- **The Obsidian / NeuroVault claim was withdrawn.** That Markdown-vault sync was never implemented — there is no `src/obsidian.rs` in any commit, no `neurostrata_sync_obsidian` MCP tool, and no `obsidian-sync` CLI subcommand. `docs/ops/obsidian.md`, `docs/UI_GUIDE.md`, `docs/FEATURES.md`, `docs/README.md`, `docs/COGNITIVE_ARCHITECTURE.md` and `docs/science/nomenclature.md` now say so plainly, and point at the tracking task `neurostrata-dlag`.
- **The secret scanner was described as redacting with `[REDACTED]` markers.** It does not redact — `src/secrets.rs` fails closed and rejects the write outright, so a credential never reaches a vector index, the Episodic Buffer, or a Git-shared mesh record.
- **The global namespace was described as a directory.** The embedded skill file pointed at `~/.config/neurostrata/global/`. There is no such directory: `global` is a namespace column in the same LadybugDB store, and the config file is `~/.config/neurostrata/config.json`.
- **Verification.** 1,496 Rust tests pass with 0 failures (`cargo test --locked -- --test-threads=1`), the build is warning-free, and `neurostrata-mcp --version` reports `1.16.0`. 136 plugin tests pass with 0 failures: `plugins/core` 73, `plugins/opencode` 13, `plugins/claude` 11, `plugins/codex` 11, `plugins/github-cli` 11, `plugins/hermes` 11, `plugins/openclaw` 6.

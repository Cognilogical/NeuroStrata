# What's New in 1.17.3 — Verified WAL Recovery, Retrieval Correctness & Formal Verification

> This release captures everything merged to `main` since **v1.17.1**, including the version-corrected 1.17.2 changes that were committed but never tagged.

- **Verified WAL and snapshot recovery (`#170`–`#172`, `#189`–`#196`, `#198`).** Strict WAL verification fails closed by default. Operator-approved recovery replays a valid committed prefix, checkpoints it, and reopens under strict verification while preserving unclean or corrupted WAL artifacts. New no-open storage inspection, checksummed backup, snapshot verification, and restore-to-path commands support recovery without opening a damaged store. Backup and restore copies are atomic, snapshot retention covers recovery artifacts, store provenance is explicit, and oversized checkpoints no longer retry indefinitely. See `docs/runbooks/wal-recovery.md` before changing the strict-WAL default.
- **Retrieval and file-recall correctness (`#116`, `#120`, `#121`, `#127`, `#149`, `#197`, `#200`).** Both lexical routes enforce active-generation visibility, object ACLs, and current-state filtering at query, merge, and hydration. Literal code-token filters run before `TopDocs`; mention caches are namespace-scoped; file recall omits the domain-registry row and puts newer, more specific memories first.
- **Ingest and generation lifecycle (`#108`, `#112`, `#126`, `#142`, `#147`–`#149`).** Ingest aborts instead of publishing after unreadable files, carry-forward failures, or summary failures that require a full reparse. No-change ingests retain the active generation, file-to-directory transitions publish correctly, and skipped files are reported with bounded reasons. Namespace-scoped generation retention safely preserves active, rollback, staging, and base generations.
- **Security and authorization hardening (`#147`, `#158`, `#162`, `#169`, `#177`, `#183`).** Secret scanning distinguishes source expressions, comments, and configuration literals while still rejecting real provider tokens and JWTs; metadata updates and live ingest use the same scanner. `set_metadata` re-checks write access and restricts owner/ACL changes. Repository-file extraction is linear-time, vulnerable dependencies are refreshed, CodeQL findings are resolved, and Podman sandbox scripts arrive over `stdin` rather than the process command line.
- **Formal verification (`#167`).** A pure Rust formal kernel mirrors nine state-machine domains. The Lean 4 suite proves 53 theorems, while 421 parity rows check the Rust implementation against the models. SynapticMesh supersession now preserves concurrent edits on archived records.
- **Performance and memory controls (`#107`, `#109`, `#114`, `#117`, `#188`).** The store buffer pool defaults to 384 MB and the CPU embedding arena is opt-in. CPU embeddings are batched, AST ingest runs in parallel, blocking work moves off the async runtime, hygiene repair is batched, and longitudinal benchmark receipts track performance. Daemon RSS/growth reporting and runtime knobs are documented in `docs/limitations.md` and `docs/BUILDING.md`.
- **Task, guard, and harness reliability (`#101`, `#105`, `#106`, `#151`, `#173`–`#176`).** Zero-Action checks consider only task rows, guard candidates are listed deterministically, and concurrent guard hit counts are atomic. Strict pre-push checks now block only unfinished claims on the current branch or worktree, allowing independent efforts to push without hiding extraction, P0, or rule-provenance violations. The remediation eval registry and gate receipt bind claims to tested heads. Setup accepts an empty embedder list, installer repair preserves custom hook commands, and daemon/event tests isolate token state and avoid mutating their source folders.
- **CI and release gates (`#163`, `#165`, `#185`–`#187`).** Windows and macOS suites run report-only, script and plugin suites run in CI, and core dependencies plus Tree-sitter 0.27 are updated. Every tag must match `Cargo.toml` and pass the binary test suite before release binaries can build or publish.
- **Also included from the untagged 1.17.2 commit (`#64`, `#66`–`#67`, `#71`, `#78`).** Fresh installs can choose a permanent embedding model, store identity is carried through backup/restore and enforced against model changes, the stdio proxy resolves daemon tokens per request, and LadybugDB is pinned to `lbug` 0.22.3.

## Upgrading

When upgrading from 1.17.2 or earlier, the parser-version bump forces one full reparse/re-embed. Keep at least 2× store size free; the preflight refuses an upgrade the host cannot hold. A pre-1.17.3 lexical index is rebuilt once (`INDEX_VERSION` v2). Read `docs/ops/upgrading.md` for disk, buffer-pool, rollback, and `files_skipped` guidance.

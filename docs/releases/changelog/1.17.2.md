# What's New in 1.17.2 — Embedding Model Choice at Setup, Store-Identity Hardening & lbug 0.22.3

> 1.17.2 is the first version-stamped build of the changes first published as the **v1.17.1** pre-release. That tag was cut without a version bump, so its binary reports `1.17.0`; 1.17.2 carries the identical code with the version and changelog corrected.

- **Embedding model choice at initial setup (`src/model_choice.rs`, `#66`).** On a fresh install the first interactive command offers a one-time choice among measured embedding-model candidates, so a deployment can run a smaller resident footprint than the FP32 default. The daemon never prompts and declining keeps the default. The pick is permanent once a store holds data: the store now records its embedding model in a `ladybug.db.store-state.json` sidecar (carried by backup and restore, including `scripts/backup.sh`), and a store with recorded data refuses vector operations under a different model, same-width switches included. Existing stores are untouched; migrating one to a different model is not included.
- **Store-identity defects from the #66 review are fixed (`#78`, closing `#73`, `#74`, `#75`, `#76`).** `guard_first_write` now covers fresh-unrecorded stores; fresh-store provenance survives non-serving opens; the daemon-stopped fallback paths (Add, Edit, Ingest) initialize the store; and `export_database` no longer leaves a stale destination sidecar or WAL when a snapshot directory is reused. `scripts/test-backup.sh` adds automated coverage of the backup sidecar carry. Recording identity for legacy (pre-sidecar) stores is tracked in `#77` and is **not** part of this release.
- **The stdio MCP proxy resolves the daemon bearer token on every forwarded request (`src/server.rs`, `#64`).** The proxy used to snapshot `daemon.token` once at construction, so a slow first start left it without a credential and every forwarded request returned 401 until restart; a rotated token stranded a running proxy the same way. The token is now read per attempt, covering both cases.
- **`lbug` (LadybugDB) bumped from 0.20.4 to 0.22.3 (`#67`)**, with `LBUG_VERSION` pinned to the crate version in `ci.yml`, `nightly.yml` and `release.yml` (`#71`) so CI and releases build against the engine archive the lockfile names. This bump makes no claim about the engine abort tracked in LadybugDB #1536.

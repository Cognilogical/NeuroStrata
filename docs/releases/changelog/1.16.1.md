# What's New in 1.16.1 — An Honest Validator, Corrected 1.16.0 Notes

- **The SHACL checker no longer calls an object-valued `metadata.source` blank (`src/rdf/shacl.rs`).** It judged a rule's provenance with `source.as_str().map(|s| s.trim().is_empty()).unwrap_or(true)`. `as_str()` returns `None` for a JSON object, so `unwrap_or(true)` marked every object source as blank and reported `"source must be non-blank for a rule"`. An object source is legal and in active use: `add_memory` declares `source` with type `["string","object"]`, the rule-source backfill in `src/server.rs` treats a non-string source as *present* (so it is not backfilled), `supersede_memory` accepts an object source, and the canonical predicate `crate::traits::has_source` in `src/traits.rs` reads a non-empty object as sourced. The task gate (`src/task/gate.rs`) and the search ranker (`src/store/ladybug.rs`) both already called `has_source` — only the SHACL checker had drifted, so the validator disagreed with the gate it ships beside. It now calls `has_source` instead of carrying a second copy of the rule, so the three surfaces cannot drift apart again. The two messages stay distinct: an absent source is `"source is required for a rule"`, a source that is present but unusable provenance (null, a blank string, an empty object, a number, a boolean, an array) is `"source must be non-blank for a rule"`, and a non-empty string or a non-empty object is accepted. In the `NeuroStrata` namespace this removed 8 of the 10 reported shape warnings; the 2 that stay are retired rows that genuinely carry no source.
- **The hygiene repair no longer destroys a structured `metadata.source` (`src/store/ladybug.rs`).** `repair_namespace_hygiene` read a rule's source with `meta.get("source").and_then(|v| v.as_str()).unwrap_or("")`, so an object source read as blank and `neurostrata-mcp repair-hygiene` overwrote the structured provenance with the row's location (or `"legacy-rule"`) — the repair destroyed the origin it was meant to preserve. It now asks `crate::traits::has_source`, the same predicate the task gate and the SHACL checker use, and only repairs a source that is genuinely absent or unusable; the `"N/A"` placeholder is still repaired.
- **The four false claims from the 1.16.0 documentation sweep are corrected.** (1) The tool count is **56**, not 51: `src/server.rs:840` appends the 6 SynapticMesh tools to the 50 in the `tools/list` array, and the order-pinning test `tools_list_carries_all_thirty_six_tools_in_a_stable_order` pins all 56 by name. (2) The pre-push gate blocks on more than its three *task* conditions — it also blocks on *rule honesty* (a live rule with no `metadata.source`, an unknown `metadata.enforcement`, an `ENFORCED` claim naming a missing or advisory guard, a `PARTIAL` claim without a real guard, a `NOT_ENFORCED` claim that still names one, or a guard with no enforcement value). (3) `oxiri` was missing from the semantic-web crate list — it is a direct dependency. (4) The mesh subcommand list omitted the hidden `sync-enqueue`, the pre-push hook's internal pull-then-push target.
- **The Nightly workflow builds again.** Two independent causes, confirmed against the run logs: `nightly.yml` never received the vendored-OpenSSL configure step the other two workflows carry (Windows), and the Linux job referenced an `include_str!` of a `plugins/opencode/dist/index.js` bundle that was not tracked in git (since fixed by the #52 merge).

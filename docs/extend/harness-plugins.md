# Agent Harness Plugin Interface

## `@neurostrata/plugin-core` Architecture

`@neurostrata/plugin-core` is the zero-dependency harness plugin bundle shipped under `plugins/core/`. It provides a universal adapter that wraps the NeuroStrata daemon/MCP server and exposes hooks for agent harnesses:

- `createHarnessPlugin` — factory that builds a plugin instance for a specific harness
- `handleHookEvent` — dispatches hook events (PreToolUse, PostToolUse, SessionStart, etc.) to the daemon
- `resolveProjectRoot` — walks up from a working directory to find the project root
- `discoverProjectNamespace` — the last step of the namespace order below: `.NeuroStrata/session_queries.json`, else the project folder's name
- `findRootMarker` — finds the project root marker for a folder, mirroring `neurostrata-mcp`'s walk (checked against the shared cases in `tests/fixtures/root-marker-cases.json`)

### Namespace order

`resolveConfig` uses the same order as `neurostrata-mcp namespace resolve`:

1. The project root marker, `<root>/.NeuroStrata/config.json` (`{"version": 1, "namespace": "..."}`), found from the project folder: the deepest marker in the folder's own checkout, or in its main checkout for a linked worktree; outside git, the first marker above the folder. A `.NeuroStrata` that is a link pointing elsewhere is not a marker.
2. The harness plugin config the installer writes, passed to the plugin as its config.
3. `NEUROSTRATA_NAMESPACE` from the environment.
4. `discoverProjectNamespace`.

The installer writes one config file per harness, each naming the namespace:

| Harness     | Config file                                                                                         |
| ----------- | --------------------------------------------------------------------------------------------------- |
| Claude Code | `.NeuroStrata/plugins/claude/neurostrata.json` (`{"id": "neurostrata-claude", "namespace": "..."}`) |
| OpenCode    | `.opencode/neurostrata-plugin.json` (`neurostrata.namespace`)                                       |
| Codex       | `.codex/plugins/neurostrata.json` (hooks: `.codex/hooks.json`)                                      |
| Hermes      | `.hermes/plugins/neurostrata.json`                                                                  |
| OpenClaw    | `.openclaw/plugins/neurostrata.json`                                                                |
| GitHub CLI  | `.NeuroStrata/plugins/github-cli/copilot-extension.json` (hooks: `.github/hooks/neurostrata.json`)  |

Each CLI hook runner (`cli-hook.mjs`) reads its harness's config file (`readHarnessConfig`) and passes it to the plugin as config; the plugin reads `NEUROSTRATA_NAMESPACE` itself, in its own place in the order. The runner the installer writes to `<root>/.NeuroStrata/plugins/<harness>/` reads `<root>`'s config first, then the one at the project folder's checkout top (and its main checkout's, for a linked worktree). The Claude hooks (PreToolUse, SessionStart, Stop, SessionEnd, PreCompact) run `node "<runner>"`, with no namespace in the command. An older install's `NEUROSTRATA_NAMESPACE=<ns> node "<runner>"` commands are repaired by the installer: the first namespace they name (SessionStart, then PreToolUse, then Stop) is written to Claude's config file and read back before the commands lose it; if that fails, those commands stay as they are and the install reply carries a warning. A fresh install whose config file cannot be written still installs the hooks, with the same warning.

The Claude runner resolves from the session's project folder, not the folder of each event (Claude Code starts a new hook process per event, and the event's `cwd` follows `cd`): `CLAUDE_PROJECT_DIR`, which Claude Code exports to hook processes as the project root where the session started; without it, the folder recorded for the session at SessionStart (`claude_session_dirs` in `.NeuroStrata/active_session.json`). A session started inside a split subfolder with its own marker therefore uses that subfolder's namespace. SessionStart also fires on resume, clear and compact; a folder already recorded for the session is kept. The file is replaced whole (a temporary file and a rename), and left alone when it exists but cannot be parsed.

A marker that exists but cannot be read (not JSON, `version` other than the integer 1 (`1.0` included), a missing or invalid `namespace`) is skipped with one warning line on stderr naming the file, and the order continues with the harness config; `neurostrata-mcp namespace resolve` fails on the same file instead.

The installer adds its runner to each Claude hook event (PreToolUse, SessionStart, Stop, SessionEnd, PreCompact; the last two let the runner write the handoff note) that has no entry running it yet, beside the user's own entries, and leaves settings that run another install's `cli-hook.mjs` as they are. An older install's commands that named different namespaces all move to the first one; the install reply then carries a warning naming them. Only a plain `node "<runner>"` command whose runner is the installer's own, or sits at `.NeuroStrata/plugins/claude/cli-hook.mjs` (a moved project's), is repaired.

**Claim scope from a linked worktree.** `neurostrata_task_claim` and `neurostrata_get_snapshot` without `worktree`, `project_root` or `cwd` are scoped by the daemon to the namespace's registered root, the main checkout once a project marker applies. The plugins pass the session's project folder as `worktree` on those calls when they name none: OpenCode and Hermes in their before-tool hooks, and every CLI hook runner in its PreToolUse reply (`updatedInput`). For Claude the installer adds a PreToolUse entry with the matcher `mcp__.*__neurostrata_(task_claim|get_snapshot)`. Without the argument the registered root (the main checkout) is used.

**Tool names.** Harnesses prefix MCP tools: OpenCode names them `<server>_<tool>` (`neurostrata_neurostrata_task_claim`), Claude Code and Codex `mcp__<server>__<tool>`. The plugins map every spelling to the bare `neurostrata_<tool>` name (`canonicalToolName` in core, copied in Hermes) before any check against a NeuroStrata tool: claim and memory-write tracking, the session-scoped tools, and the NeuroStrata tools whose results get no task-intent reminder, because a task note or memory they return is stored data, not new work.

Without `.git` above the folder, `findProjectRoot` takes the nearest folder holding a valid marker, else the nearest folder holding `.NeuroStrata`, but never the home folder: `~/.NeuroStrata` holds the user's own state, not a project's.

The plugin is harness-agnostic: the same `createHarnessPlugin` function works for OpenCode, Claude, Hermes, and Codex because it only depends on the harness hook interface, not on harness internals.

Codex CLI runs hooks only from `.codex/hooks.json` (or `[hooks]` in its `config.toml`), so for Codex the installer adds a `PreToolUse` hook for `apply_patch|Bash`, a second `PreToolUse` hook for `mcp__.*__neurostrata_(task_claim|get_snapshot)` (Codex names MCP tools `mcp__<server>__<tool>` in hook payloads and matchers, and accepts an `updatedInput` rewrite of their arguments, so a claim carries the session's folder), and `SessionStart`, `Stop`, `SessionEnd` and `PreCompact` hooks (no matcher) there, next to any existing entries. `SessionStart` lets the runner inject the session's starting context from `.NeuroStrata/active_session.json`; `SessionEnd` and `PreCompact` let it write the handoff note. The hook command is `node '<runner>'`: the path is single-quoted so `$` or backticks in it never expand (Codex runs hook commands through PowerShell on Windows and `sh` elsewhere; in the PowerShell form every quote PowerShell recognizes, typographic ones included, is doubled), and it carries no namespace, because the callers that refresh it (`get_snapshot`'s hook hygiene, `hooks install`, daemon boot) only have a folder-name guess; the runner takes the namespace from `.NeuroStrata/neurostrata-plugin.json` when it has one, else discovers it. Every runner passes a namespace to `initialize` only when `NEUROSTRATA_NAMESPACE` is set, so an unset variable never overrides the configured one. Later runs recognize the installer's own hook (exactly `node '<root>/.NeuroStrata/plugins/codex/cli-hook.mjs'`, from this or a moved checkout) and repoint it to the current runner; any other command, including a user's own `cli-hook.mjs` elsewhere or one that runs the runner and more, is left as written. Codex sends `apply_patch` input as `{"command": "<patch>"}`; file-touch recall reads the patch path from `command`. `Stop` and `SubagentStop` are answered with `{"continue": true}`, because Codex rejects a `Stop` reply that carries a permission decision. Codex asks the user to review a new hook once and runs project hooks only in a trusted project. A `hooks.json` with an event list that is not an array is left alone with a warning, since Codex parses the file as a whole.

Copilot CLI runs hooks only from the repository's `.github/hooks/*.json` files (hooks file `version` 1, camelCase event names), never from `.NeuroStrata/plugins/github-cli/copilot-extension.json`. The installer therefore keeps its own file, `.github/hooks/neurostrata.json`, with one entry for each of `sessionStart`, `sessionEnd` and `preCompact`: `{"type": "command", "bash": "node '<runner>'", "powershell": "node '<runner>'", "env": {"NEUROSTRATA_HOOK_EVENT": "<event>"}}`. The installer adds the same entry for `preToolUse` when the bundled plugin answers in Copilot's reply shape (exports `copilotPreToolUseReply`), and for `postToolUse` when it handles that event (exports `handlePostToolUseEvent`); otherwise it removes the one it wrote earlier. A `postToolUse` reply can carry the session-start text a slow start missed and rules a reply left out: Copilot appends its `additionalContext` to the tool result the model sees, while a `preToolUse` reply carries no text on an allowed call. The runner (the installer's and each package's `cli-hook.mjs`) answers `{}` to `postToolUse` when the plugin bundle does not export `handlePostToolUseEvent`. A failed hook replies by event: `Stop` gets `{}` with exit code 2, `preToolUse` a deny, and every other event `{}`. `bash` uses `sh` quoting and `powershell` PowerShell quoting, on every platform; neither carries a namespace. Copilot's hook input does not name the event, so the runner reads it from `NEUROSTRATA_HOOK_EVENT`. Later runs repair the installer's own entry in place: only a `bash` or `powershell` command that runs the runner is rewritten, a missing one is added, and its other keys and `env` entries stay. Every other entry and key stays. A file that is not a JSON object, has another `version`, or has an event list that is not an array (Copilot then rejects the whole file) is left alone with a warning. The file carries an absolute path, so it is added to the git exclude file (for a linked worktree, the one in the common git directory, which every worktree reads).

## Session- & worktree-aware task state

`resolveActiveTaskFromDaemon` never picks the first `in_progress` task blindly. Among in-progress tasks it prefers, in strict order: an explicit `preferredTaskId`, a task matching both `activeSessionId` and the current `effectiveProjectRoot`, a task matching `activeSessionId`, a task matching the worktree, then any in-progress task. A fallback owned by a different session never overwrites a known `activeSessionId`, which prevents cross-session / cross-worktree Breath bleed between child worktrees.

`inspectCodeModeExecution` detects key presence (`id`, `session_id`, `note`) even when the value is a variable or template literal — for example `neurostrata_task_claim({ id: created.id, session_id: ses.id })` or a note built as a Breath template literal. Such a claim is marked as claimed but clears any stale `activeTaskId`, so the next check re-resolves the real id from the daemon using `activeSessionId`. Explicit `undefined`/`null` values are not treated as real keys.

`isZeroActionExemptShellPayload` (exported from `plugins/core`) keeps the Breath mutation counter from advancing on provably read-only / verification shell commands only. It accepts `bash`/`shell`/`command`/`exec` tools, unwraps JSON `{command, cmd}` payloads, and uses a fail-closed allowlist: read-only git subcommands (`status`, `log`, `diff`, `show`, `rev-parse`, `fetch`, `stash list|show`, read-only `branch` flags), `neurostrata-mcp task|doc-gate|synaptic-mesh status`, the `cargo` check/test family, read-only `gh` subcommands and `gh api` without write flags, `node --test` / `*test.mjs`, gate-receipt scripts, and `rustc --version`. Substitutions, redirection, and chains containing any non-exempt segment fail closed. The `neurostrata_guard_validate` call itself is never skipped for an exempt command.

`neurostrata-nb9q`: both hook call sites (`executeBeforeHandler` and `handleHookEvent`) pass `is_mutating: !shellExempt` to `neurostrata_guard_validate`. The daemon does not trust this caller-declared value: it recomputes the shell verdict from the raw payload through the shared kernel (`src/formal_kernel.rs`, `is_zero_action_exempt_shell_payload`), so an under-reporting plugin cannot bypass the active-task gate. Exempt verification commands — including `git push`/`git pull` after `neurostrata_task_complete` — therefore avoid the Lock 2 / push Catch-22 in both surfaces. Force-push flags (`-f`, `--force`, `--force-with-lease`) inside short bundles (`-vf`, `-uf`), forced refspecs (`+main`), `--mirror`, `--delete`, `--prune`, and backgrounded shells (`CMD &`) stay mutating; `&&` chains of read-only commands stay exempt. Both implementations are pinned to one checked-in verdict corpus (`tests/fixtures/shell-exemption-verdicts.json`) plus Lean parity, so the two verdicts cannot drift silently.

Both call sites forward the analysable tool input as the guard payload. A raw-string input — notably Codex `apply_patch` (`input: "*** Update File: …"`) — is sent as the patch text itself instead of the `{}` that `firstRecord` would produce, so the daemon's file-mutation extraction can see the target and content. Object inputs remain JSON-encoded; the mutation counter and the Zero-Action shell exemption keep using the canonical payload.

Claude Code `NotebookEdit` is a file-mutating tool like `Write` and `Edit`: it is in `MUTATING_FILE_TOOLS`, so its input (including the cell body in `new_source`) reaches `neurostrata_guard_validate`, and its `notebook_path` drives file-touch recall. The Claude hook the installer writes matches `Read|Write|Edit|MultiEdit|NotebookEdit|Bash|Task`; an install that still has the older matcher without `NotebookEdit` is widened on the next install or init.

`neurostrata-1e14`: subagent context headers sanitize namespace and task labels to `[A-Za-z0-9_.:-]` before interpolation. Code Mode's `execute`/`mcp_execute` tool output is also excluded from task-intent intake.

`neurostrata-nb9q`: subagent graph-first injection is agent- and harness-aware: read-only subagents (`reviewer`, `checker`, `checker-free`, `explore`) receive a skip note instead of directives to call MCP tools they do not have, and Code Mode harnesses reference `execute` with `tools.neurostrata.*`. Intent extraction from `read`/`grep`/`glob`/shell tool output is suppressed, because `TODO:`/`defer` in stdout or source comments is not a task obligation; user and assistant turns still nudge.

## Generational Context Graph L1 Working-Set Garbage Collector (`neurostrata-zji8`)

`@neurostrata/plugin-core` implements an $O(1)$ per-turn Generational Context Graph L1 Working-Set Garbage Collector (`WORKING_SET_MAX_FRAME_BYTES = 4096` UTF-8 bytes) backed by `.NeuroStrata/active_session.json#working_set` (`WORKING_SET_SCHEMA_VERSION = 1`). Instead of accumulating unbounded recall blocks or tool outputs in the prompt history, the working-set engine maintains four tiers (`Immortal`, `PinnedRoot`, `YoungGen`, `EvictedStub`) whose eviction precedence (`evaluateWorkingSetEviction`) is formally verified across 2,560 truth-table parity rows in `src/formal_kernel.rs::evaluate_working_set_eviction` and `proofs/NeuroStrata/WorkingSetGc.lean`:

- **Metadata-only persistence:** `.NeuroStrata/active_session.json#working_set` stores only bounded node metadata, pointer lines, and SHA-256 digests (`tool_output_digests`); raw tool outputs and private memory contents are never persisted to disk.
- **Dehydration and delta frame rendering:** Read-only inspection tool outputs exceeding `TOOL_GC_INLINE_THRESHOLD_BYTES = 3072` bytes or repeating an identical canonical read in the same epoch are dehydrated into bounded UTF-8 head/tail previews (`512` head + `512` tail bytes) plus deterministic 1-line pointer stubs (`[NeuroStrata GC Stub -> ...]`). `renderWorkingSetFrame` and `upsertWorkingSetFrame` inject or replace the `[NeuroStrata Active Context] ... [NeuroStrata End Active Context]` frame in place only when its SHA-256 `frame_fingerprint` changes.
- **Delta-only frame injection:** The `changed` flag in `runWorkingSetToolCycle` and `runWorkingSetContextCycle` gates whether the `[NeuroStrata Active Context]` frame is injected as `additionalContext` in `PostToolUse`, `SessionStart`, and `Stop` CLI replies. `runWorkingSetToolCycle` captures `beforeFingerprint` and `beforeInjected` prior to mutation, evaluates `final.fingerprint !== beforeFingerprint && final.fingerprint !== beforeInjected`, and persists `last_injected_fingerprint` when `changed && !input.advanceTurn`, while `runWorkingSetTurnBoundary` carries `last_injected_fingerprint` forward when only `turn_seq` incremented. `wsReplaceCompleteFrames`, `wsStripFrames`, and `wsRecallMemoryIds` use linear `indexOf` scanning instead of regex backtracking, preserving text before the first open tag and avoiding polynomial ReDoS on uncontrolled recall text.
- **Six-harness lifecycle & installer wiring (`src/task/harness_plugins.rs`):**
  - **OpenCode, Claude Code, Codex, and GitHub CLI** build thin adapters via `plugins/core/bundle-adapter.mjs`; **OpenClaw** and **Hermes** compile against `@neurostrata/plugin-core` via `bundle-adapter.mjs --compiled-adapter`, emitting deterministic 4-artifact bundles (`dist/index.{js,js.map,d.ts,d.ts.map}`) across all 7 packages (28 artifacts total).
  - The Rust installer wires native lifecycle hooks for Claude (`SessionStart`, `PreToolUse`, `PostToolUse`, `Stop`), Codex (`SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`), and GitHub CLI (`.github/hooks/neurostrata.json` with `sessionStart`, `userPromptSubmitted`, `preToolUse`, `postToolUse`, `agentStop` plus `.git/info/exclude`), preserving foreign hooks and refusing symlinks.

### Three-tier KV-cache projection (`neurostrata-zji8` Task 5)

`plugins/core/index.ts` projects the working set into three KV-cache tiers without ever calling an LLM:

- **Tier 0 (`renderWorkingSetTier0Prefix`):** immortal Golden Rules only, capped at `WORKING_SET_TIER0_MAX_BYTES = 2048`. `evaluateWorkingSetCacheTier` routes `Immortal` nodes with a system channel to `tier0_system_prefix`; the text contains no turn, epoch, or task counters, so its SHA-256 fingerprint is byte-identical across turns and task updates. On OpenCode V2 `{ system, messages }` events, `upsertWorkingSetSystemPrefix` replaces this prefix in `event.system` in place.
- **Tier 1 (`projectWorkingSetMessages`):** quantized history folded at `WORKING_SET_STRIDE_MESSAGES = 8` boundaries, keeping a `WORKING_SET_HOT_TAIL_MESSAGES = 12` hot tail. `computeWorkingSetQuantizedFrontier` and `evaluateWorkingSetStrideFold` mirror `src/formal_kernel.rs` exactly (8 cache-tier and 128 stride-fold rows). Protected system/pinned messages and every message at or beyond the frontier are retained verbatim; folded buckets become deterministic stubs, so the prefix is byte-identical within a stride bucket.
- **Tier 2 (`renderWorkingSetDeltaFrame`):** volatile task header, roots, young gen, typed `working_set.edges`, and stubs. Edges use `WorkingSetEdgeKind` (`GOVERNS`, `DEPENDS_ON`, `CALLS`, `IMPORTS`, `CONCEPTUAL_BRIDGE`, `EXTRACTED_FROM`), deduplicated by `(from, kind, to)` and capped at `WORKING_SET_MAX_EDGES = 128`. `upsertWorkingSetMessageTailDelta` attaches the delta to the tail of `event.messages` on OpenCode V2 and to `additionalContext` on the CLI adapters, bounded so Tier 0 + Tier 2 never exceed `WORKING_SET_MAX_FRAME_BYTES = 4096`.

`sessionPromptHandler` registers as `ctx.session.hook("prompt")` and the Claude runner handles `UserPromptSubmit`: `runWorkingSetPromptCycle` extracts `file:`, `symbol:`, `mem:`, and project-relative path anchors with a linear tokenizer, then applies deterministic 1-hop (`GOVERNS`/`EXTRACTED_FROM`/`CONCEPTUAL_BRIDGE`) and 2-hop (structural edge → `GOVERNS`) spreading activation before the model call. Cyclic edges terminate via a visited key; page-faulted stub neighbors are promoted through the existing ReBAC-filtered expansion callback. `sessionCompactionHandler` replaces the lossy host LLM summary with `event.result = { summary }` from `renderWorkingSetCompactionSummary`, preserving Golden Rules, active task, roots, edges, and stub restore pointers in a deterministic bounded payload. Older v1 snapshots with no `working_set.edges` load with `edges: []`.

## Implementing a New Harness Adapter

To add a new harness adapter:

1. Create a new entry under `plugins/<harness>/` mirroring the structure of `plugins/core/`
2. Call `createHarnessPlugin(pluginId, harnessName)` to obtain a plugin object
3. Register the plugin's hooks with the target harness using `handleHookEvent` as the handler
4. Ensure `resolveProjectRoot` and `discoverProjectNamespace` are wired into the harness's project-root discovery

The adapter must not hardcode the project name or namespace; both are discovered at runtime from the workspace filesystem.

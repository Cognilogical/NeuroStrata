# SynapticGraph — Dual-Track Bi-Temporal Graph & Semantic Reasoning Engine

> **Why you care:** Memory is a relational graph, not a flat pile of text chunks. SynapticGraph connects architectural rules directly to the source files, AST symbols, tasks, and ontological shapes they govern—while preserving an immutable bi-temporal audit trail of every change.

---

## 1. Storage Foundation: Embedded LadybugDB

At the heart of SynapticGraph (`src/store/ladybug.rs`) is **LadybugDB**, an embedded property graph and HNSW vector engine compiled directly into the `neurostrata-mcp` binary:
- **Zero External Database Containers:** Runs in-process from `~/.config/neurostrata/data/db`.
- **Unified Node & Edge Store:** Stores cognitive Engrams (`rule`, `fact`, `procedure`, `task`, `attempt`) alongside structural code nodes (`directory`, `file`, `symbol`) in a single transactional graph.
- **Typed Directed Edges:**
  - `GOVERNS` — Links a `rule` or `fact` to the exact file, directory, or AST symbol it constrains.
  - `DEPENDS_ON` — Captures architectural and module dependencies.
  - `RELATES_TO` — Connects associative memories across domains.
  - `EXTRACTED_FROM` — Links lessons and rules back to the completed `task` that proved them (Lock 2).
  - `CONTAINS` / `CALLS` / `IMPORTS` — Structural edges generated by the Tree-sitter AST indexer.

---

## 2. Bi-Temporal Immutability (`valid_from` / `valid_to`)

Agents never overwrite or erase historical decisions in place:
1. Every memory node is stamped with a `valid_from` Unix timestamp upon creation and `valid_to: 0` (active).
2. When an architectural rule evolves, calling `neurostrata_supersede_memory` stamps `valid_to` on the predecessor node, creates the replacement node with a new `valid_from` timestamp, and records `metadata.superseded_by`.
3. Retrieval surfaces (`neurostrata_search_memory`, `neurostrata_get_snapshot`, `neurostrata_memories_for_file`) automatically filter for active nodes (`valid_to == 0 || valid_to > now`) while allowing historical time-travel queries and audit trails.

---

## 3. 11-Language Tree-sitter AST Code Graph (`src/parser/ingest.rs`)

Running `neurostrata_ingest_directory` (or `neurostrata-mcp ingest`) parses your repository using compiled Tree-sitter grammars across **11 languages** (Rust, TypeScript, JavaScript, Python, Go, C, C++, Java, Ruby, Bash, HTML/CSS):
- Extracts functions, structs, classes, traits, interfaces, methods, call sites, and imports.
- Automatically materializes `GOVERNS` edges from existing rules to matching files and symbols via the Thalamic Bus post-ingest normalizer.
- Enables `neurostrata_memories_for_file` to return both direct file rules and 1-hop symbol/dependency rules before an agent edits a single line of code.

---

## 4. W3C Semantic Web & Graph Intelligence Layer

Beyond property-graph traversal, SynapticGraph embeds three complementary graph-intelligence engines:

| Engine | Module | Capability |
| :--- | :--- | :--- |
| **OxiRS Semantic Web (`RDF / SPARQL 1.1 / OWL 2 RL / SHACL`)** | `src/rdf/` | Projects graph nodes into W3C RDF triples, executes federated SPARQL 1.1 queries (`neurostrata_sparql_query`), materializes transitive OWL 2 RL inferences (`neurostrata_owl_reason`), and validates writes against versioned Turtle SHACL shapes (`src/schemas/shacl/`). |
| **Leiden Community Detection** | `src/community.rs` | Clusters densely connected memory and AST nodes into hierarchical communities with modular cohesion scores. |
| **TransE Knowledge Graph Embeddings (KGE)** | `src/kge.rs` | Trains structural vector embeddings (`h + r ≈ t`) over graph triples (`neurostrata_kge_train`) for link prediction and relational similarity. |

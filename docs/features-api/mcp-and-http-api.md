# MCP Tools & HTTP Daemon API Reference

## Core Memory & Graph Retrieval Tools

- `neurostrata_add_memory` — store an architectural rule, project pattern, or task insight. For a `rule`, an omitted or blank `metadata.source` is backfilled with the resolver's project-relative spelling when a root places the location (`project_root`, else the registered root, else the nearest `.git`), otherwise exactly `"agent"`. An explicit caller-supplied source is never overwritten. Because `source` is published to mesh peers and exported, this implicit source never holds an absolute local path that names the author's machine.
- `neurostrata_search_memory` — query memory contents via vector + graph RAG (accepts optional `project_root` alongside `path_prefix` for multi-form relative/absolute prefix resolution, including root-equal prefixes that match in-root relative and absolute paths).
- `neurostrata_get_snapshot` — fetch current task state snapshot (<=800 chars).
- `neurostrata_supersede_memory` — replace active version with new one atomically.
- `neurostrata_memories_for_file` — inspect governing memories for a given path/file.
- `neurostrata_related` — find related entities (`CONTAINS`, `GOVERNS`; accepts optional `project_root`, resolves multi-form file seeds to one canonical in-namespace file node before single traversal, and returns additive `resolved_seed` metadata).
- `neurostrata_diff_tour` — diff tour between versions (separates caller-facing display paths from internal multi-form lookup paths and records canonical project-relative paths in the Graph-First session ledger).
- `neurostrata_locate` — locate structural code symbols and governing rules (resolves `path_prefix` against optional `project_root` and the namespace's cached `registry_root` across relative and absolute stored spellings, failing closed on unresolvable absolute prefixes).
- `neurostrata_insights` — evaluate and track architectural insights (accepts optional `project_root`; resolves `path_prefix` dynamically at `snapshot`/`series` time for `lexical` and `ast_calls` insights across relative and absolute stored spellings, failing closed on unresolvable absolute prefixes).
- `neurostrata_ingest_directory` — ingest a directory into the property graph. On success the resolved directory is auto-registered as a watched root, so subsequent filesystem changes are re-ingested incrementally by the daemon watcher through the same generation ingest path; a failed ingest registers nothing.
- `neurostrata_watch_status` — read-only report of registered watch roots. Optional `namespace` filters the report. Returns a JSON report (no state mutation). Available over MCP and as `GET /ingest/watch/status` on the daemon.
- `neurostrata_unwatch` — stop watching a registered root. Requires `namespace` and `dir_path`. The path is resolved through the daemon's J6 caller-path policy (startup root + `allowed_external_dirs`); a path outside those bounds is refused. Returns `{"removed": bool, "namespace": string, "canonical_path": string}`, matching `POST /ingest/watch/unwatch`. The `canonical_path` echo is produced by the core's J6 resolver, so it matches the path actually unregistered even when the caller supplied a relative path or one with a non-existent tail. On Windows resolved paths drop the `\\?\` prefix where Windows allows it (`C:\...` or `\\server\share\...`); a path longer than `MAX_PATH` keeps it.
- `neurostrata_ingest_bounded` — ontology-scoped bounded RDF classification + ingest (Capability F). Inputs: `namespace`, `domain`, `candidates` (all required), optional `principal`, `user_id`, `reason`. Each candidate carries `subject`, `class`, `predicate` and an `object` that is either `{"iri": "<absolute-iri>"}` or `{"literal": {"value": "...", "datatype"?: "<iri>", "language"?: "<tag>"}}`. The requested `domain` is normalized before the governed class/predicate closure is selected under a fixed finite query budget; `governs_class` is exact-match only, so invented IRIs that collapse onto a slug are rejected. Finite caps apply to candidate count (256), IRI length (2048 bytes) and literal length (65536 bytes). The emitted Turtle and the `MemoryPayload` are SHACL-validated before any write; any violation, unknown/empty domain, budget exhaustion, ungoverned class/predicate, malformed term or cap breach fails closed with `{"ok": false, "error": ...}` and zero writes. A successful call commits exactly one idempotent batch memory (`bounded-ingest-<sha256>`) and returns `{"ok": true, "id", "namespace", "domain", "triple_count", "turtle"}`. A ReBAC namespace write gate (`can_write_namespace` on the resolved principal) protects the write; there is no permissive opt-out and no CLI/daemon surface for this tool.
- `neurostrata_append_log` — append conversational transcript log entries.
- `neurostrata_bootstrap` — initialize a new project namespace.
- `neurostrata_task_setup` — configure task scaffolding.
- `neurostrata_call_hierarchy` — traverse the knowledge hierarchy.
- `neurostrata_find_references` — locate referenced entities.
- `neurostrata_find_duplicate_candidates` — locate duplicate memory candidates.

`neurostrata_memories_for_file` (and the file part of `neurostrata_context_plan`) accepts an absolute file path as well as one relative to the ingested root. An absolute path is made relative to the caller's `project_root` when it contains the file, else to the namespace's registered project root when that root exists on this machine, else to the nearest ancestor that holds `.git` (a directory, or the `.git` file of a linked worktree). A nested repository inside the root rejects only that known root and falls through to another known root before the `.git` fallback; when no valid known root remains, it is left as given and matches nothing. A linked worktree under a project registered at a subdirectory, and a file in another repository, are left as given and match nothing when a known root exists; without one they fall back to `.git`. A linked worktree of a project registered at its checkout root resolves against that worktree. A supplied `project_root` constrains that fallback even when it is unusable on this machine (for example a moved root), so a file in another repository still stays `Outside`; an unusable registered root is ignored. If the registered root cannot be read from the store, an absolute path given without `project_root` is not placed by falling back to `.git`: `neurostrata_memories_for_file` answers it with an error, and `neurostrata_context_plan` (which takes no `project_root`) leaves that file out and marks the plan partial. Path comparison normalizes separators and drive letters, not case; the file system decides case through each path's canonical form. The store is also queried with the caller's absolute spelling, and a relative path also joined onto a known root, so memories stored with absolute paths are still found; stored memories are not rewritten. Hits from every spelling are merged by memory id and cut to the requested `limit` (at most 20); the file's symbols and imports in the reply are read with the same spellings. `..` is resolved on disk, and a symlinked file is looked up both under its target and as the caller spelled it. When the file's project marker (`.NeuroStrata/config.json`, looked for from the file's own folder up to the top of its checkout, and in the main checkout for a linked worktree; a file symlink is not followed for this) names the call's namespace (case does not matter, but a stored namespace spelled exactly as the marker owns it) and its folder is the namespace's cached project root, the path below that folder is also queried, whatever `project_root` the caller sent. `neurostrata_memories_for_file` and `neurostrata_context_plan` query it first and every spelling above after it; `neurostrata_related`, which starts from the first spelling that names a file node, queries it after every other spelling. In every other case the marker changes nothing in the lookup: a marker of another namespace, a marker whose folder is not the cached root, a marker that cannot be read, or a cached root that cannot be read. `neurostrata_memories_for_file` then adds one `root_hint` line, also on an error reply: the namespace that owns the file, a hint to run `neurostrata-mcp root show` (or `neurostrata-mcp hooks install` when the namespace has no cached root), or a warning naming the file. `neurostrata_context_plan` and `neurostrata_related` reply as before and write that line to the daemon log. Relative paths and directory prefixes are not affected. The response still echoes `path`; for an absolute path it adds `resolved_path` and `resolved_from`: `project_root`, `registry_root`, `root_config` (the project marker's folder), `marker` (the nearest ancestor holding `.git`, as before) or `outside`. `project_root` still selects the ingest generation; a root found by the lookup does not.

## Additive Agent-Adoption Contract Fields

Several tools now append advisory metadata without changing existing result fields. All additions are optional for callers and fail soft.

- `neurostrata_search_memory` defaults `mode` to `hybrid` (vector + reciprocal-rank fusion + bounded graph expansion). The legacy `include_related` argument remains accepted as a deprecated alias of `include_references` and returns the exact warning `'include_related' is deprecated; use 'include_references'`. Every response path, including hard errors, appends a `search_contract` block carrying the resolved default mode, any deprecation warning, and a `graph_expanded_ids` array. Expansion failure yields an empty id array and preserves the primary result. When `include_references` is true, citations come from each result's `metadata.edge_sources`; vault declaration reconciliation retires an entry together with the edge it cites, including when a note's final WikiLink is removed, so a deleted relationship is never cited. An unchanged declarer rebound to a newly imported preferred target keeps a citation for the live edge: the replacement edge is stamped with declaration provenance before the stale alias entry is retired. Replacement removes only the citation for the binding being rebound, so a note that also retains another declaration, or rebinds several targets in one import, keeps exactly one citation per live target. Replay citations are keyed by relationship as well as endpoint: when one head declares two relationships to the same target (for example both `related_to` and `depends_on`), replay materialises both edges and `include_references` reports one citation per relationship instead of letting one overwrite the other.
- `neurostrata_memories_for_file` adds `status`, `next_actions`, and `suppressed_reason` on success, unsupported, and query-failure paths. It declares two optional inputs that drive escalation: `staged_file_count` (integer) and `diff_text` (string, the staged unified diff bound to the `T_DIFF` prescription). Both stay out of `required`; callers that omit `diff_text` get an honest abstention with `suppressed_reason` instead of an un-dispatchable `T_DIFF`. Escalation is conditional: `related(max_hops: 2)` at high blast radius, `diff_tour` with multiple staged files, `object_view` for conceptual bridges. Ordinary single-file edits produce no graph action. `next_action` arguments are schema-valid for the named tool (`diff_tour` receives `namespace` and `diff_text`, never a `git_ref`).
- Task and subagent context carries a bounded set of real graph edges with governing rules emitted first and a hard prompt-length ceiling. Expansion errors set `expansion_error` and drop only store-sourced edges; metadata edges survive.
- `neurostrata_task_validate` exposes `advisories.graph_ontology` derived from post-dispatch receipt events. Advisories are strictly non-blocking and never appear under `violations`. A high-blast advisory clears only on an exact prescribed-action proof — a `related` call with the triggering seed and `max_hops: 2` — not on any one-hop lookup. Each `related` escalation's `next_action.args` carries an additive `followed_trigger_id` that binds the follow-through proof to the trigger actually followed (`T_HIGH_BLAST` vs `T_SEED_EXPAND`); a `related` call without a compatible hint mints no proof rather than defaulting to high-blast, so one escalation cannot clear another. `T_DIFF` and `T_STRATEGIC` proofs are likewise bound to their prescribed action and require a non-empty outcome; `T_DIFF` abstains with `suppressed_reason` when `diff_text` is empty. The canonical routing contract (named triggers, `next_action`, abstention) lives in `task::routing` (`agent_routing_contract_json` / `evaluate_triggers`) and is emitted by `handle_task_update`; legacy `graph_queries_count` and `graph_lookup_nudge` fields remain present for older callers.
- Graph-tool receipts are recorded after dispatch with real outcomes, latency, and digests. MCP `tools/call` post-dispatch receipt completeness is 100%; daemon HTTP REST and CLI surfaces are not recorded (spec §2 Non-Goals). Explicit `failed` statuses are classified as failures rather than empty results, and search receipts count the real results from the rendered text report. Receipt ledgers resolve the project root from the validated caller worktree (worktree marker), then the namespace registry, then the daemon working directory, so receipts, snapshot readiness, and validation read the same ledger. The pre-commit hook is advisory only and never fabricates receipt rows.

When a task is in progress and a project root is known, `neurostrata_get_snapshot` writes that task's block to `.NeuroStrata/active_session.json` as cached at claim time, minus the entries whose memory was superseded, expired or archived since, and minus the Cross-Domain Bridges whose path runs through such a memory. Those memories are read by id in one query; if they cannot be read, the cached block is written whole.

## Central Executive Task & Procedure Tools

- `neurostrata_task_create` — create a new task. Like `neurostrata_task_claim`, it answers with `auto_retrieved_context` and `subagent_prompt_injection`; see the note under `neurostrata_task_claim`. Its reply carries `history_count` instead of the note history.
- `neurostrata_task_list` — list tasks. Each row carries `history_count` (the number of notes in its history); `include_history: true` returns the notes themselves.
- `neurostrata_task_claim` — claim exclusivity over a task and stamp caller `worktree`/`branch` scope (from explicit `worktree`/`branch`/`project_root` arguments or the namespace's registered `project_root`). Without those arguments the registered root is used, which for a namespace with a project marker is the main checkout, so a claim from a linked worktree would carry the main checkout's branch; the harness plugins therefore pass the session's project folder as `worktree` on `neurostrata_task_claim` and `neurostrata_get_snapshot` calls that name none. A claim that takes the task (from open, or from a stale holder) returns its whole note history, so a new session sees where the work stopped; a repeat claim by the session that already holds it returns `history_count` instead.
  The reply's `auto_retrieved_context` is trimmed by default: each memory in `golden_rules`, `items`, `normative_memories` and `structural_anchors` is one row with `id`, `memory_type`, `location` and `snippet` (plus `deprecation_banner` or `not_definition` when the memory has one, and the symbol names under the same keys and shapes as in the memory's metadata: a code row's `symbol` string, and a rule or fact's `refs` entries that name a symbol, as `{file, symbol}` objects), and the context's `note` field says how to get more: `neurostrata_get_memory` with `id` and `namespace` for one memory's whole text (a golden rule not found in the task's namespace is in `global`), and `include_metadata: true` for every row's details. `include_metadata` works on `neurostrata_task_create` and on the `neurostrata_task_claim` call that takes the task; a repeat claim by the session that already holds the task returns no `auto_retrieved_context`. The other keys are unchanged. Pass `include_metadata: true` (default `false`) to get each memory's full row with its metadata; that reply has no `note`. `subagent_prompt_injection` is the same either way.
- `neurostrata_task_update` — update status/notes on a task. The reply carries the history entry this call added as `appended` (null when it added none) and `history_count` instead of the whole history.
- `neurostrata_task_complete` — finish a task (requires extracted memory → Lock 2). Like `neurostrata_task_create`, its reply carries `history_count` instead of the note history.
- `neurostrata_task_validate` — advisory gate report for a task.
- `neurostrata_procedure_perform` — fire a recurring procedure.
- `neurostrata_guard_validate` — validate PreToolUse actions against behavioral rules and Zero-Action Start (`git push`/`pull`/`fetch`/`status`/`log`/`diff`/`show`/`rev-parse` without file-output or exec-override flags like `--output`/`-c`, plus `neurostrata-mcp task` commands, are exempt from requiring an `in_progress` task so post-completion pushes pass without skipping the gate). `neurostrata-1e14`: force-push flags and destructive remote operations (`-f` in any short bundle such as `-vf`/`-uf`, `--force`, `--force-with-lease[=<ref>]`, `+<refspec>`, `--mirror`, `--delete`, `--prune`) are never exempt — both the plugin and daemon classifiers reject them so remote-history rewrites still require an active task.

Active-task resolution is session/worktree scoped: when the daemon returns several `in_progress` tasks, resolution prefers an explicit `preferredTaskId`, then a task whose `session_id` and `worktree` both match the caller's session and project root, then a session-only match, then a worktree-only match, and only then any in-progress task. A fallback task owned by a different session does not overwrite an already known `activeSessionId`.

On the daemon side, a task's stamped `worktree` is compared with the caller's root as a location, not as a string, so the verbatim `\\?\C:\...` form a claim stores on Windows matches a caller's plain `C:\...`. This applies to `neurostrata_get_snapshot`'s pick for `.NeuroStrata/active_session.json`, graph-query stamps, tool receipts, `neurostrata_guard_validate`, and the strict push gate. The snapshot names the in-progress task claimed in the caller's worktree. It never names a task claimed in another worktree or one with no worktree stamped.

`neurostrata_guard_validate` unwraps a JSON shell payload via its `command`/`cmd` field when deciding whether a shell command is a read-only/verification exemption. The proxy caller's `cwd` (or `workdir`) is propagated into the guard request, with `worktree` defaulting to that `cwd`, so scope checks use the caller's real working tree rather than the daemon process directory. The `is_mutating` flag on the wire is client-supplied and untrusted; the daemon recomputes shell mutability from the raw payload and never trusts it.

## Enterprise Ontology, Digital Twins, Scenarios & Kinetic Actions

- `neurostrata_scenario` — define counterfactual scenarios. Operations: `create`, `stage_memory`, `stage_twin`, `apply_action`, `evaluate_sparql`, `diff`, `plan_ontology_diff`, `commit`, `drop`, `list`.
- `neurostrata_twin_get` / `neurostrata_twin_set` / `neurostrata_twin_diff` / `neurostrata_twin_list` — manage polymorphic digital twin state.
  - `plan_ontology_diff` is a zero-mutation dry run (`POST /scenario` shares this same handler). It clones the active namespace RDF — or the named `scenario_id` overlay — into an ephemeral in-memory dataset, applies `add_turtle` (Turtle/N-Quads) and `retract_triples` (canonical N-Triple/N-Quad patterns), validates the post-image against `candidate_shacl_turtle` (or the governing shapes) via `ontobug::validate::shacl_turtle`, and returns a `plan` report: certified Capability A `added_entailments` (`DerivationStep`s) and `removed_entailments`, `validation_conforms`, `new_shacl_violations`, `consistency_violations`, ReBAC-filtered `impacted_memories`/`impacted_files`/`impacted_action_slugs` (from changed governance facts and SPARQL ASK outcomes), and `schema_ddl_diff` from `ontobug::diff_ontologies` + `generate_cypher_ddl`. Nothing is committed to a store, scenario, task, edge or the ontology cache.
- `neurostrata_action` — apply kinetic actions (state-machine mutations) via `POST /action`.

## Central Agentic Kernel & DataConnector Tools

- `neurostrata_data_connector` — execute an `AgentKernel` connector command: `list_connectors`, `describe_pool`, `register_pointer`, `list_pointers`, `resolve_pointer`, `apply_effect`, `mediate` (runtime dispatch also accepts `register_pool`, `upsert_pool`, and `list_pools`). The MCP `tools/list` disclosure for its `args` object is operation-discriminated (`oneOf` on `operation`): each variant lists its own required fields and the nested `DataPointerRecord`, `DataSliceRequest`, and `ExternalEffectRequest` layouts. Omitted `namespace` defaults to `"global"`. Pointer reads (`list_pointers`, `resolve_pointer`, `mediate`) require a named `principal`: an omitted principal is rejected at the external boundary with `{"ok": false, "error": ...}` before any pointer or connector I/O, and only kernel-internal reads use the port's trusted `None` path. Denied responses are non-disclosing: neither pointer identifiers nor record content appear in the error or in any log message. Other operations keep `principal` optional; present non-string, blank/whitespace, or whitespace-padded `namespace` and `principal` values are rejected at the handler boundary before constructing `AgentKernel`. Optional `now_secs` (u64) on `resolve_pointer`, `apply_effect`, and `mediate` defaults to the current epoch when omitted; the schema is discovery-only and runtime validation is unchanged.

## Vault-LD Markdown Sync

- `neurostrata_vault_sync` — bidirectional W3C YAML-LD 1.0 / Vault-LD Markdown sync with Open JSON Canvas 1.0 topology export. `action='export'`: one Markdown note per readable memory (ReBAC `can_read_memory` filter on `principal`), plus `topology.canvas` of the note graph grouped by epistemic tier. `action='import'`: walks the vault for `*.md`, secret-scans (`SecretScanner::scan_str`) and SHACL-validates (`ontobug::validate::shacl_turtle`, `Mode::Native`) every note BEFORE any store write — violations skip the note, never partially store it. Unresolved `[[WikiLinks]]` materialize as `stub: true` notes. Inputs: `action` (`export`|`import`, default `export`), `namespace` (default `NeuroStrata`), `vault_path` (required), `output_dir` (export only; defaults to `vault_path`), `principal` (ReBAC principal, optional). Over HTTP the daemon validates `vault_path`/`output_dir` against its startup root and `allowed_external_dirs` before any filesystem access; over CLI/MCP the process cwd is the J6 boundary.

`POST /vault-sync` is the Vault-LD Markdown sync route; `vault_path` and `output_dir` are resolved against the daemon startup root or an explicit allowed external directory before any filesystem access.

`POST /cli/root` is how `hooks install` and `root set` set a namespace's cached root through a running daemon (`{"op": "cache_root", "namespace", "root"}`). The `root` is a caller path: it must resolve inside the daemon startup root or an `allowed_external_dirs` entry (refused with `403` otherwise, the same rule as `/ingest`), and it must hold a project marker for the namespace. The route only writes the registry row.

All endpoints are served by the **neurostrata-mcp daemon** on `127.0.0.1:34343`. Tauri acts as a lightweight HTTP client; Cursor MCP integration proxies stdio JSON-RPC requests.

When `store.max_db_bytes` (or `NEUROSTRATA_MAX_DB_BYTES`) is set, a write that would carry the store past the cap is refused before it reaches the engine. The tool call fails with `ERROR [STORE_FULL]` naming the current size and the cap, and the store's contents are unchanged; the daemon-memory advisory points buffer-pool failures at `NEUROSTRATA_BUFFER_POOL_BYTES` / `store.buffer_pool_bytes`. An over-cap store still opens so it can be read, archived, and pruned.

At startup the daemon refreshes the harness plugin files in its startup root and in every configured project (the folder that holds the project's `.NeuroStrata` folder). Each harness keeps the namespace its own config already names, looked up in the folder itself first, then in its checkout and the main checkout; configs that disagree are left as they are. A harness with no config, or whose config cannot be read, gets its plugin files only, so the daemon never writes an empty or made-up namespace into a harness config (see `namespace resolve` in the CLI reference).

`POST /mcp` follows JSON-RPC 2.0: a method the server does not implement gets error `-32601` (method not found) with the request's `id`, `ping` gets an empty result, and a notification (no `id`) gets `202 Accepted` with an empty body. For an unknown method, an explicit `"id": null` is a request id, not a notification: it receives the `-32601` response above with `"id": null`; only an omitted `id` suppresses the reply.

## Storage Status Surfaces

`storage status` has two provenance layers since #212. The path-only (no-open) surface — used by the CLI's dispatch and by callers that must not open the store — reports filesystem and store-state sidecar facts: `wal_bytes`, `wal_age_secs` (age of the active WAL, regular files only), `checkpoint_failures`, and the persisted `last_recovery { at, kind, wal_bytes }` history. The live-handle surface additionally owns `opened_via_recovery` and its kind _exclusively_: a verified live store never reports recovery because the sidecar holds a `last_recovery` entry. Identity writes (`has_data`, descriptor) and health writes (checkpoint health) are split (`write_store_state_identity` vs. the health writers), and a fresh process still reports the last real checkpoint because `record_checkpoint_outcome` persists to the sidecar (best effort, never propagated).
